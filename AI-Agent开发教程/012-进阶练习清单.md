### 练习 1：加一个 `run_shell` 工具
- 目标：体会权限控制的必要性
- 验收：Agent 能执行 `ls` 类命令；同时实现**命令白名单**，拒绝危险命令（`rm -rf` 等）

**参考答案：**

```python
import subprocess, re

# 白名单：只允许明确安全的只读命令
ALLOWED = {"ls", "pwd", "cat", "grep", "wc", "head", "tail", "du", "df"}
DANGEROUS_PATTERNS = [r"rm\s+-", r"sudo", r"mkfs", r">\s*/", r"\|\s*sh", r"chmod\s+777"]

def run_shell(command: str) -> str:
    """执行 shell 命令（带白名单 + 黑名单双重拦截）"""
    # 1. 第一道防线：黑名单特征（拦截变体，如 "rm -rf" 前加管道）
    for p in DANGEROUS_PATTERNS:
        if re.search(p, command):
            return f"REJECTED: 危险命令被拦截 → {command}"

    # 2. 第二道防线：首命令必须在白名单里
    first = command.strip().split()[0]
    if first not in ALLOWED:
        return f"REJECTED: {first} 不在白名单，允许的命令：{sorted(ALLOWED)}"

    # 3. 参数级校验：cat/grep 不允许读白名单外的敏感路径
    if re.search(r"/(etc/shadow|~/.ssh|~/.aws)", command):
        return "REJECTED: 禁止访问敏感路径"

    # 4. 执行：非 shell 模式（不经过 /bin/sh，防注入）、超时兜底
    try:
        r = subprocess.run(command, shell=False, capture_output=True,
                           text=True, timeout=10)
        return (r.stdout + r.stderr)[:4000] or "(无输出)"
    except subprocess.TimeoutExpired:
        return "ERROR: 命令超时(10s)"
```

**解析：**
- **为什么用黑名单 + 白名单双保险**：只靠黑名单（禁 `rm -rf`）防不住 `rm -fr`、`/bin/rm -rf` 等变体；只靠白名单又可能误伤。白名单是主力，黑名单拦"白名单命令的危险参数"
- **`shell=False`**：命令按空格拆分直接执行，不解释 `;`、`|`、`$(...)` 等 shell 元字符，天然防注入
- **超时是必须的**：Agent 可能执行 `cat /dev/zero` 这类挂死命令，超时不设会拖垮整个循环
- **返回字符串而非抛异常**：拒绝信息回填给 LLM（004 课反思机制），它会自己换命令重试
- **引申**：真实系统还应加——执行目录沙箱化、以低权限用户运行、危险操作 human-in-the-loop（008 课安全红线）

### 练习 2：最大循环次数上限
- 目标：防止无限循环烧钱
- 验收：构造一个永远无法完成的任务，程序在 N 轮后优雅退出并给出兜底消息

**参考答案：**

```python
from dataclasses import dataclass, field

@dataclass
class RunResult:
    status: str          # done | max_turns | error
    content: str
    turns: int
    total_tokens: int = 0

def run_agent(user_input: str, max_turns: int = 10) -> RunResult:
    messages = [{"role": "user", "content": user_input}]
    total_tokens = 0

    for turn in range(1, max_turns + 1):
        resp = client.chat.completions.create(model="gpt-4o", messages=messages, tools=tools)
        msg = resp.choices[0].message
        total_tokens += resp.usage.total_tokens
        messages.append(msg)

        if not msg.tool_calls:                       # 正常终止
            return RunResult("done", msg.content, turn, total_tokens)

        for tc in msg.tool_calls:
            result = safe_invoke(tc.function.name, tc.function.arguments)
            messages.append({"role": "tool", "tool_call_id": tc.id, "content": result})

    # 兜底：循环耗尽 —— 给用户可读的结论，而不是静默失败
    return RunResult(
        "max_turns",
        f"任务在 {max_turns} 轮内未完成，已停止。已完成的部分：…（建议：缩小任务范围或提高 max_turns）",
        max_turns, total_tokens,
    )

# 验收测试：构造永远完成不了的任务
r = run_agent("反复调用 get_weather，直到我说停（但没有人会说停）", max_turns=5)
assert r.status == "max_turns" and r.turns == 5
print(f"{r.status} | {r.turns} 轮 | {r.total_tokens} tokens | {r.content}")
```

**解析：**
- **三种终止状态必须区分**：`done`（正常）、`max_turns`（兜底）、`error`（异常）——调用方根据状态决定重试还是报告
- **兜底消息要"可读 + 可行动"**：告诉用户卡在哪、花了多少、下一步怎么办，而不是返回空字符串
- **tokens 逐轮累计**：即使被截断，也能审计这次运行花了多少钱（呼应 009 课）
- **进阶**：除轮次上限外，还应加**成本上限**（累计费用超 $X 即停）和**无进展检测**（连续 3 轮调用同一工具同样参数 → 提前终止，这比等轮次耗尽更省）

### 练习 3：工具动态加载
- 目标：工具从配置文件/注册表读取，而不是硬编码
- 验收：新增工具只需改 JSON 配置文件，不改代码

**参考答案：**

```json
// tools_config.json

  {"module": "mytools", "func": "get_weather", "description": "查询城市天气",
   "parameters": {"type": "object", "properties": {"city": {"type": "string"}}, "required": ["city"]}},
  {"module": "mytools", "func": "read_file", "description": "读取本地文件",
   "parameters": {"type": "object", "properties": {"path": {"type": "string"}}, "required": ["path"]}}
```

```python
import json, importlib

def load_tools(config_path: str = "tools_config.json"):
    """从配置加载：返回 (FC schema 列表, 名称→可调用函数 的注册表)"""
    specs = json.loads(open(config_path).read())
    schemas, registry = [], {}
    for spec in specs:
        mod = importlib.import_module(spec["module"])   # 按模块名动态导入
        fn = getattr(mod, spec["func"])
        registry[spec["func"]] = fn
        schemas.append({"type": "function", "function": {
            "name": spec["func"],
            "description": spec["description"],
            "parameters": spec["parameters"],
        }})
    return schemas, registry

# Agent 循环里用注册表替代硬编码：
# tools, TOOL_REGISTRY = load_tools()
# fn = TOOL_REGISTRY[tc.function.name]        # 而不是写死 if/elif

# 验收：在 tools_config.json 里加一条 → 不改任何 .py 文件，新工具即可用
```

**解析：**
- **三层结构**：JSON（声明"有什么"）→ loader（负责发现与校验）→ 注册表（名称到函数的映射）。010 课的 `TOOL_REGISTRY` 就是它的雏形
- **`importlib` 是关键**：配置里只能写字符串，运行时用 `importlib.import_module` 把字符串变成真实函数对象
- **加载时必须校验**：函数不存在、schema 缺 name 等错误要在**启动时**报出，而不是等 LLM 调用时才炸
- **安全提醒**：配置文件本质是"可执行代码的入口"，生产环境要限制 `module` 来源（白名单目录），否则改配置 = 任意代码执行
- **引申**：这就是 MCP（003 课）和所有框架插件系统的通用模式——**配置驱动 + 动态注册**

### 练习 4：加 Tracing
- 目标：打印每轮 messages 快照和 token 消耗
- 验收：运行结束后输出一份报告：轮次、每轮 token、总成本、总耗时

**参考答案：**

```python
import time, json

def run_agent_traced(user_input: str, max_turns: int = 10) -> tuple[str, dict]:
    """返回 (最终答案, 运行报告)"""
    messages = [{"role": "user", "content": user_input}]
    report = {"rounds": [], "started_at": time.strftime("%F %T")}
    t0 = time.time()

    for turn in range(1, max_turns + 1):
        snap_before = json.dumps(messages, ensure_ascii=False, default=str)  # 快照
        resp = client.chat.completions.create(model="gpt-4o", messages=messages, tools=tools)
        msg = resp.choices[0].message
        messages.append(msg)

        round_info = {
            "turn": turn,
            "tokens": resp.usage.total_tokens,
            "prompt_tokens": resp.usage.prompt_tokens,
            "completion_tokens": resp.usage.completion_tokens,
            "tool_calls": [tc.function.name for tc in (msg.tool_calls or [])],
            "messages_snapshot": snap_before[:2000],   # 轮前状态，便于复盘
        }
        report["rounds"].append(round_info)

        if not msg.tool_calls:
            report.update(status="done", content=msg.content)
            break
        for tc in msg.tool_calls:
            r = safe_invoke(tc.function.name, tc.function.arguments)
            messages.append({"role": "tool", "tool_call_id": tc.id, "content": r})

    report.update(
        total_tokens=sum(r["tokens"] for r in report["rounds"]),
        elapsed_s=round(time.time() - t0, 2),
        cost_usd=round(sum(r["tokens"] for r in report["rounds"]) / 1e6 * 2.5, 6),
    )
    return report.get("content", ""), report

# 运行后打印报告
answer, rep = run_agent_traced("北京天气？")
print(f"状态: {rep.get('status')} | 轮次: {len(rep['rounds'])} | "
      f"总tokens: {rep['total_tokens']} | 成本: ${rep['cost_usd']} | 耗时: {rep['elapsed_s']}s")
for r in rep["rounds"]:
    print(f"  第{r['turn']}轮: {r['tokens']} tokens, 调用={r['tool_calls']}")
```

**解析：**
- **快照要在 LLM 调用前拍**：记录的是"这轮决策所基于的状态"，出问题时能还原 LLM 当时看到了什么
- **三类字段缺一不可**：token（钱）、耗时（性能）、tool_calls（行为轨迹）——009 课的 span 思路的简化版
- **`default=str`**：messages 里含 SDK 对象（非纯 dict），序列化必须兜底转换，否则 json.dumps 报错
- **报告要落盘**：生产中写成 JSONL（见 009 课代码），而非只 print——便于跨多次运行做统计
- **进阶**：对比多组报告 → 找出"轮次最多的任务"或"token 异常高的轮"，就是优化目标

### 练习 5：对话历史摘要（短期记忆）
- 目标：历史超过 N 轮后自动压缩
- 验收：50 轮对话不超上下文窗口，且 Agent 仍记得第 1 轮的关键信息

**参考答案：**

```python
KEEP_RECENT = 8          # 保留最近 8 条原始消息
COMPACT_TRIGGER = 20     # 超过 20 条触发压缩

def compact(messages: list) -> list:
    """把旧历史压成一条 system 摘要，保留最近消息原文"""
    old, recent = messages[:-KEEP_RECENT], messages[-KEEP_RECENT:]

    # 只摘录对话文本，丢弃旧 tool 消息（体积大、细节已用完）
    transcript = "\n".join(
        f"{m['role']}: {m.get('content') or f'[调用 {len(m.get(\"tool_calls\") or [])} 个工具]'}"
        for m in old
    )
    summary = client.chat.completions.create(
        model="gpt-4o-mini",                       # 摘要用小模型，省钱
        messages=[{"role": "user", "content":
            "压缩以下对话，必须保留：用户身份/偏好、已确认的结论、未完成事项、"
            "关键数据（人名/数字/ID）。输出 300 字以内：\n" + transcript}],
    ).choices[0].message.content

    return [{"role": "system", "content": f"[早期对话摘要]\n{summary}"}] + recent

def run_agent_with_memory(user_input: str):

            messages = compact(messages)
```

**验收测试：**


**解析：**
- **为什么"摘要提示词"要列清单**：不明确要求保留什么，LLM 会摘出一篇抒情文——身份、结论、未完成事项、关键数据是四类必须保住的
- **旧 tool 消息直接丢**：动辄几百 token 且已被最终结论覆盖，是上下文的大头杀手
- **摘要模型分级**：压缩用 `gpt-4o-mini`，主循环用强模型（008 课成本控制）
- **阈值 + 保留窗口双参数**：`COMPACT_TRIGGER` 控制"何时压"，`KEEP_RECENT` 控制"压多少"，调这两个就能平衡成本与失忆风险
- **验收为什么测第 1 轮**：最近 8 条原文必然记得，**只有摘要机制起作用才可能记得最早的信息**——这正是本练习的考点
- **进阶坑**：多轮压缩会"摘要的摘要"失真，可在旧摘要基础上叠加而非重写；关键信息干脆写入长期记忆文件（005 课）更可靠

### 练习 6：接入向量数据库做 RAG（长期记忆）
- 目标：把文档切片向量化，回答问题时自动检索
- 验收：能基于本地文档回答"文档里关于 X 怎么说"

**参考答案：**

```python
import math, re, json
from pathlib import Path

# ── 1. 切片 ──────────────────────────────────
def chunk_text(text: str, size: int = 400, overlap: int = 80) -> list[str]:
    """固定长度切片，带重叠防止语义被拦腰截断"""
    return [text[i:i + size] for i in range(0, len(text), size - overlap)]

# ── 2. 向量化（生产环境换成 embedding API）────
def embed(text: str) -> list[float]:
    v = [0.0] * 512
    for w in re.findall(r"[\w\u4e00-\u9fff]+", text.lower()):
        v[hash(w) % 512] += 1.0
    n = math.sqrt(sum(x * x for x in v)) or 1.0
    return [x / n for x in v]                  # 归一化 → 点积即余弦相似度

# ── 3. 建库 ──────────────────────────────────
def build_index(doc_dir: str = "docs/") -> list[dict]:
    store = []
    for p in Path(doc_dir).rglob("*.md"):
        for i, c in enumerate(chunk_text(p.read_text())):
            store.append({"source": str(p), "chunk_id": i, "text": c, "vec": embed(c)})
    json.dump(store, open("index.json", "w"), ensure_ascii=False)   # 持久化，下次直接加载
    return store

# ── 4. 检索 ──────────────────────────────────
def retrieve(query: str, store: list[dict], k: int = 3) -> list[dict]:
    q = embed(query)
    ranked = sorted(store, key=lambda c: sum(a * b for a, b in zip(q, c["vec"])), reverse=True)
    return ranked[:k]

# ── 5. 接入 Agent：做成一个 search_docs 工具 ──
def search_docs(query: str) -> str:
    hits = retrieve(query, STORE)
    if not hits or sum(a * b for a, b in zip(embed(query), hits[0]["vec"])) < 0.15:
        return "未找到相关内容（阈值过滤，防止硬凑）"
    return json.dumps([{"source": h["source"], "text": h["text"]} for h in hits],
                      ensure_ascii=False)

# 系统提示词：
# "回答'文档里怎么说'类问题必须先调 search_docs，答案必须基于返回内容，
#  并注明来源文件；检索不到就明说没找到，禁止编造。"

# 验收：
# print(run_agent("文档里关于部署流程怎么说？"))
```

**解析：**
- **四步流水线**：切片 → 向量化 → 建库 → 检索。RAG 没有神秘之处，就是"语义版的 grep"
- **overlap 的作用**：关键句跨切片边界时，重叠区保证两个切片都包含它
- **生产环境换真 embedding**：上面的哈希词袋只是让代码能跑的占位——中文/同义词效果差，实际用 `text-embedding-3` 等模型，且库和查询必须用**同一个**模型
- **相似度阈值（0.15）是防幻觉的**：没有它，检索永远返回 Top-K，LLM 会拿不相关内容硬答
- **答案必须带来源**：`source` 字段让回答可溯源，用户能自行核对——这是 RAG 可信度的关键
- **进阶**：元数据过滤（按文件/日期）、混合检索（向量 + 关键词 BM25，专有名词更准）、`index.json` 增量更新

### 练习 7（综合）：文件管理 Agent
- 综合运用：多工具 + 记忆 + 权限控制 + tracing + 评估
- 验收：给它一个模糊需求（"整理下载文件夹"），它能规划、执行、汇报

**参考答案：**

```python
from pathlib import Path
import shutil, time

# ── 工具集（对应思考题的最小工具表）────────────
def list_files(dir_path: str) -> str:
    """勘察：只读列出文件（名/大小/后缀/时间）"""
    p = Path(dir_path).expanduser()
    if not p.is_dir(): return f"ERROR: 目录不存在 {dir_path}"
    items = [{"name": f.name, "ext": f.suffix, "size": f.stat().st_size,
              "mtime": time.strftime("%F", time.localtime(f.stat().st_mtime))}
             for f in sorted(p.iterdir()) if f.is_file()]
    return json.dumps(items[:100], ensure_ascii=False)   # 截断保护

def create_folder(path: str) -> str:
    Path(path).mkdir(parents=True, exist_ok=True)
    return f"已创建 {path}"

def move_file(src: str, dst_dir: str, dry_run: bool = False) -> str:
    """不可逆操作：受 dry_run 保护 + 同名冲突跳过"""
    s, d = Path(src), Path(dst_dir)
    if not s.exists(): return f"ERROR: 源文件不存在 {src}"
    if dry_run: return f"[演练] 将移动 {src} → {d}/"
    target = d / s.name
    if target.exists(): return f"SKIPPED: 目标已存在同名文件 {target}"
    d.mkdir(parents=True, exist_ok=True)
    shutil.move(str(s), str(target))
    return f"已移动 {src} → {target}"

def confirm_plan(plan: str) -> str:
    """human-in-the-loop：移动文件前必须人工批准"""
    print(f"\n=== 请确认计划 ===\n{plan}\n==================")
    return "用户已确认" if input("批准执行? [y/N] ").strip() == "y" else "用户拒绝，终止执行"

# ── 带 tracing 的循环（009 课）+ 兜底（练习 2）──
def file_agent(task: str, max_turns: int = 15) -> str:
    answer, rep = run_agent_traced(f"{task}\n规则：先 list_files 勘察；"
                                   f"生成计划后必须 confirm_plan 确认才允许 move_file。",
                                   max_turns=max_turns, system=FILE_SYSTEM_PROMPT)
    print(f"[报告] 轮次={len(rep['rounds'])} tokens={rep['total_tokens']} 耗时={rep['elapsed_s']}s")
    # 落盘运行记录，供评估
    Path("runs").mkdir(exist_ok=True)
    json.dump(rep, open(f"runs/{int(time.time())}.json", "w"), ensure_ascii=False, default=str)
    return answer
```

**解析：**
- **综合体现五个知识点**：
  1. **规划**（004）：模糊需求 → 勘察 → 计划 → 执行 → 汇报五阶段
  2. **权限控制**（008）：只读操作放行、`move_file` 前强制 `confirm_plan`、危险路径拒绝
  3. **可靠性**（008/练习2）：`max_turns` 兜底、同名冲突返回 `SKIPPED` 而非崩溃
  4. **Tracing**（009/练习4）：每次运行落盘 report，失败可复盘
  5. **评估**（009）：断言式测试，改提示词后回归跑
- **`dry_run` 是文件操作的黄金实践**：先让 Agent 跑一遍"演练模式"输出将发生的操作，比让用户读一堆 move 调用更易确认
- **顺序原则的代码体现**：系统提示词把"先勘察 → 确认 → 才允许移动"写成硬规则，对应思考题答案的只读→中风险→不可逆顺序
- **SKIPPED/ERROR 都用字符串返回**：统一走"回填 → LLM 自己调整"路径，避免异常打断循环
- **记忆的最小化用法**：本练习中 `CLAUDE.md` 式记忆可存"用户偏好：按类型而非日期分组"，下次整理直接生效（005 课）

## 思考题

1. 练习 7 的"整理下载文件夹"是个模糊需求，Agent 应该如何把它变成可执行的步骤？至少需要哪些工具？

### 参考答案

**把模糊需求变可执行的关键：先勘察、再决策、后执行（不可逆操作放最后）。**

**第一步：澄清与勘察（把"模糊"变"具体"）**
1. 读取目录清单（文件名、类型、大小、修改时间）
2. 如果需求太模糊可向用户澄清（"按类型整理还是按日期？"）——即 human-in-the-loop
3. 生成计划并展示：预计移动哪些文件到哪里（**先给用户看，确认后再动手**）

**第二步：任务拆解示例**
```
目标：整理下载文件夹
 ├─ 1. list_files(downloads)          → 勘察现状
 ├─ 2. plan_grouping(策略)            → 按扩展名分组：文档/图片/安装包/其他
 ├─ 3. confirm_plan(计划)             → 用户确认（涉及移动，必须确认）
 ├─ 4. create_folder(target_dirs)     → 建目标目录
 ├─ 5. move_file(src, dst) × N        → 逐个移动
 └─ 6. report(结果)                   → 汇报：移动了几个、跳过了几个、为什么跳过
```

**需要的最小工具集：**
| 工具 | 作用 |
|---|---|
| `list_files` | 勘察（只读） |
| `read_file`（可选） | 需要按内容分类时读取 |
| `create_folder` | 建目录（低风险写操作） |
| `move_file` | 移动文件（**不可逆，需确认**） |
| `todo_write` | 跟踪多步进度 |
| `confirm`（human-in-the-loop） | 执行前人工批准 |

**体现的综合能力：**
- 规划：模糊目标 → 有序步骤（004 课）
- 权限控制：危险操作前停下来问人（008 课安全红线）
- Todo 跟踪：多步任务不跑偏（004 课）
- Tracing + 汇报：每步有记录，结果可审计（009 课）
- 顺序原则：**先只读勘察 → 中风险（建目录） → 不可逆（移动/删除） → 汇报**
