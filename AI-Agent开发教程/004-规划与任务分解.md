# 004 规划与任务分解

## 本课要点

复杂任务需要拆解：

- **任务拆解**：大目标 → 子目标 → 具体步骤（Todo 管理）
- **反思与自我纠错**：检查中间结果、失败重试、回滚
- **反思实现方式**：把错误作为 tool 结果回填，LLM 会自己换方案

## 两种规划模式

| 模式 | 说明 | 适用场景 |
|---|---|---|
| Pre-planning | 执行前先生成完整计划 | 任务边界清晰、步骤可预测 |
| Interleaved | 边执行边调整计划 | 探索性任务、环境不确定 |

## 反思的实现

```python
try:
    result = fn(**args)
except Exception as e:
    result = f"ERROR: {e}"   # 错误回填，LLM 看到后自己纠错/换方案
```

不需要额外的"反思提示词"——**错误信息本身就是最好的反思信号**。

## Todo 管理

让 Agent 把计划写成可勾选的清单，每轮更新状态：
- 任务跟踪工具（read/todo_write 类工具）
- 防止多步任务中途"忘记目标"

### 代码案例：一个 todo_write 工具

```python
import json
from pathlib import Path

TODO_FILE = Path("todo.json")

def todo_write(todos: list[dict]) -> str:
    """整体覆盖更新任务清单。每项: {content, status: pending|in_progress|completed}"""
    # 校验：最多一个 in_progress
    active = [t for t in todos if t["status"] == "in_progress"]
    if len(active) > 1:
        return "ERROR: 同一时间只能有一个 in_progress 任务"
    TODO_FILE.write_text(json.dumps(todos, ensure_ascii=False, indent=2))
    return f"已保存 {len(todos)} 项任务"

def todo_read() -> str:
    """读取当前任务清单"""
    return TODO_FILE.read_text() if TODO_FILE.exists() else "（空清单）"
```

```python
# tools 列表里注册（schema 省略 properties 细节）

```

### 代码案例：两阶段规划（先规划、再执行）

```python
def run_planning_agent(task: str):
    # 阶段 1：强制先出计划（用响应格式约束，拿到结构化步骤）
    plan = llm_json(
        system="把任务拆成 3-8 步，输出 JSON 数组，每步含 action/done_when",
        user=task,
    )
    todo_write([{"content": s["action"], "status": "pending"} for s in plan])

    # 阶段 2：进入标准 Agent 循环，LLM 每完成一步就更新 todo
    return run_agent(f"任务：{task}\n计划见 todo_read()，逐步执行并更新状态")
```

**要点**：计划本身也持久化（写文件），崩溃恢复（008 课）时可从计划断点继续。

## 思考题

1. 什么时候应该让 Agent 自己规划，什么时候应该由你写死流程？

### 参考答案

判断标准：**任务的确定性 × 容错成本**。

**写死流程（代码编排）当：**
- 步骤固定且可预测（如：登录 → 查询 → 生成报表）
- 出错代价高（金融交易、不可逆操作）
- 需要低延迟、低成本（不想每步都烧 token 让 LLM 想）
- 合规要求可解释、可审计

**让 Agent 自己规划（LLM 编排）当：**
- 用户输入开放、无法预枚举（"帮我调研 X"）
- 步骤依赖中间结果、边做边才知道下一步
- 失败可以低成本重试

**实践中的混合策略（推荐）：**
```
写死的外层流程 + Agent 自主的内层执行
例：工单系统固定为「分类 → 派发 → 处理 → 回访」，
    但"处理"这一步让 Agent 自己决定查什么系统、怎么改。
```

经验法则：**框架负责确定性，LLM 负责不确定性**——能用 if/else 解决的就不要交给 LLM。
