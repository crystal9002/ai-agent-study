# 003 MCP（Model Context Protocol）

## 本课要点

工具/上下文接入的事实标准协议。

- 统一了 LLM 与外部工具、数据源的连接方式
- 一次实现，处处可用（不同 Agent、不同模型都能复用）
- 类比：**工具界的 USB 接口**

## 传统方式 vs MCP

| | 传统方式 | MCP |
|---|---|---|
| 接入新工具 | 每个应用写一套集成代码 | 写一个 MCP Server，所有支持 MCP 的 Agent 都能用 |
| 工具发现 | 硬编码在提示词里 | 动态列举（list_tools） |
| 上下文数据 | 手动拼接 | 标准化资源协议（resources） |

## 三个核心角色

1. **Host**：宿主应用（如 Claude Desktop、你的 Agent 程序）
2. **Client**：与 Server 的连接层
3. **Server**：提供工具/资源的服务（文件系统、数据库、浏览器…）

## 实践建议

- 学习路径：先会手写 Function Calling（002 课），再理解 MCP 解决的"复用"问题
- 自己写一个最小 MCP Server（几十行代码即可）

### 代码案例：30 行写一个最小 MCP Server

```python
# server.py —— 提供一个加法工具和一个静态资源
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("demo-server")

@mcp.tool()
def add(a: float, b: float) -> float:
    """两数相加"""
    return a + b

@mcp.tool()
def read_notes() -> str:
    """读取我的学习笔记"""
    return open("notes.md").read()

if __name__ == "__main__":
    mcp.run()  # 默认 stdio 传输
```

### 代码案例：客户端连接并把 MCP 工具接入 Agent 循环

```python
# client.py —— 列出工具 → 转成 FC schema → 接进 010 课的循环
import asyncio
from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client

async def load_mcp_tools():
    params = StdioServerParameters(command="python", args=["server.py"])
    async with stdio_client(params) as (read, write):
        async with ClientSession(read, write) as session:
            await session.initialize()
            tools = await session.list_tools()      # 动态发现工具
            for t in tools.tools:
                print(t.name, "-", t.description)   # 转成 tools 列表喂给 LLM
            # result = await session.call_tool("add", {"a": 1, "b": 2})

asyncio.run(load_mcp_tools())
```

**接入 Agent 的关键**：`session.list_tools()` 拿到的 schema 转换后放进 010 课 `run_agent` 的 `tools` 参数，工具执行函数改为 `session.call_tool(...)` —— 循环本身一行不用改。

## 思考题

1. MCP 和 Function Calling 是竞争关系吗？（提示：MCP 是传输层，FC 是调用方式）

### 参考答案

**不是竞争关系，是互补的两层。**

| | Function Calling | MCP |
|---|---|---|
| 是什么 | 一种**调用方式**（协议格式）：LLM 如何表达"我要调 X 工具" | 一种**连接协议**：Agent 如何发现和接入工具服务 |
| 解决的问题 | LLM 输出结构化的调用意图 | 工具的可复用、可插拔、标准化接入 |
| 层次 | 应用层 | 传输/接入层 |

协作方式：
```
LLM --Function Calling--> 你的 Agent 运行时 --MCP--> 各种 MCP Server（文件/数据库/浏览器…）
```

- 传统方式：MCP Server 暴露的工具被包装成 tools 列表 → LLM 用 FC 调用
- 换个模型/框架：只要支持 MCP，接入代码不用重写
- 结论：**FC 是"怎么调"，MCP 是"从哪接入"**，两者配合使用。
