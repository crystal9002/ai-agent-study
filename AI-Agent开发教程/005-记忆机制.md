# 005 记忆机制

## 本课要点

| 类型 | 方案 | 说明 |
|------|------|------|
| 短期记忆 | 上下文窗口管理 | 截断、摘要压缩历史对话 |
| 长期记忆 | 向量数据库（RAG） | 语义检索相关知识 |
| 结构化记忆 | 记忆文件 | Agent 自己读写笔记（如 CLAUDE.md） |

## 关键认知

**`messages` 数组就是 Agent 的工作记忆**，每轮必须完整回填，否则 LLM "失忆"。

## 三层记忆详解

### 短期（会话内）
- 最近 N 轮直接保留
- 老历史用 LLM 摘要压缩
- 超出窗口必须截断——否则 API 报错

**代码案例：超窗自动摘要压缩**

```python
MAX_KEEP_ROUNDS = 10  # 保留最近 10 轮原始消息

def compact_messages(messages: list) -> list:
    """把早期历史压缩成一条摘要，保留最近消息原文"""
    if len(messages) <= MAX_KEEP_ROUNDS * 2:
        return messages

    old, recent = messages[:-MAX_KEEP_ROUNDS * 2], messages[-MAX_KEEP_ROUNDS * 2:]

    # 只保留 user/assistant 文本，丢弃老的 tool 消息（细节反正已过期）
    transcript = "\n".join(
        f"{m['role']}: {m.get('content') or '[调用工具]'}"
        for m in old if m["role"] in ("user", "assistant")
    )
    summary = client.chat.completions.create(
        model="gpt-4o-mini",   # 摘要用便宜模型
        messages=[{"role": "user",
                   "content": f"总结以下对话要点（保留结论、决策、未完成事项）：\n{transcript}"}],
    ).choices[0].message.content

    return [{"role": "system", "content": f"早期对话摘要：{summary}"}] + recent
```

### 长期（跨会话）
- 文本 → 向量化 → 存入向量库
- 每次对话前按语义检索 Top-K 注入上下文
- 这就是 RAG

**代码案例：最小 RAG（本地文件 + 余弦相似度，零外部依赖）**

```python
import math, re

def embed(text: str) -> list[float]:        # 换成真实 embedding API 即可
    v = [0.0] * 256
    for w in re.findall(r"\w+", text.lower()):
        v[hash(w) % 256] += 1.0             # 占位：哈希词袋
    n = math.sqrt(sum(x * x for x in v)) or 1
    return [x / n for x in v]

# 建库：文档切片
chunks = [doc[i:i+500] for doc in docs for i in range(0, len(doc), 500)]
store = [(c, embed(c)) for c in chunks]

def search(query: str, k: int = 3) -> list[str]:
    q = embed(query)
    ranked = sorted(store, key=lambda c: sum(a * b for a, b in zip(q, c[1])), reverse=True)
    return [c for c, _ in ranked[:k]]

# 每次对话前注入（放进系统提示）：
context = "\n---\n".join(search(user_question))
```

### 结构化（Agent 自己管理）
- Agent 主动调用 `write_memory` 保存关键结论
- 下次启动时读取（类似 CLAUDE.md / AGENTS.md）

**代码案例：让 Agent 自己读写记忆文件**

```python
import json, time
from pathlib import Path

MEM = Path("agent_memory.json")

def memory_write(content: str, tags: list[str]) -> str:
    """保存一条记忆。Agent 应只记录：项目约定、踩过的坑、用户偏好"""
    data = json.loads(MEM.read_text()) if MEM.exists() else []
    data.append({"time": time.strftime("%F %T"), "tags": tags, "content": content})
    MEM.write_text(json.dumps(data, ensure_ascii=False, indent=2))
    return f"已保存记忆（共 {len(data)} 条）"

def memory_search(query: str) -> str:
    """按关键词检索相关记忆，最多返回 5 条"""
    data = json.loads(MEM.read_text()) if MEM.exists() else []
    hits = [m for m in data if any(t in query or query in m["content"] for t in m["tags"])]
    return json.dumps(hits[-5:], ensure_ascii=False) or "无相关记忆"
```

```python
# 系统提示词示例：
# "任务中发现可复用的结论时，调用 memory_write 保存；
#  回答前如涉及历史背景，先调用 memory_search 查询。"
```

## 思考题

1. 记忆太多会不会反而有害？如何决定"记什么"？

### 参考答案

**会。记忆不是越多越好，有害体现在三方面：**

1. **挤占上下文窗口**：无关记忆占了空间，真正相关的当前任务信息被截断——检索质量下降（"大海捞针"效应，长上下文中段信息召回率最低）
2. **引入噪声与矛盾**：过时的记忆、互相冲突的旧结论会误导 LLM（比如 3 个月前的 API 签名还留在记忆里）
3. **成本上升**：每轮都重复携带，token 费用线性增长

**决定"记什么"的四个标准：**

| 标准 | 说明 |
|---|---|
| 未来有用 | 用户偏好、项目约定、踩过的坑——下次还会遇到 |
| 事实性/结论性 | 记结论（"该项目用 pnpm"），不记过程日志 |
| 不可轻易推出 | 常识不用记，自己能查到的不用记 |
| 可验证 | 记住的信息最好带来源和时间戳，方便过期淘汰 |

**工程做法**：记忆写入前过一道 LLM 审查（"这条值得记吗？是否与已有记忆重复/冲突？"），检索时只取 Top-K 而非全量。
