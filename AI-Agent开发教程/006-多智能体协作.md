# 006 多智能体协作

## 本课要点

- **角色分工**：Planner（规划）/ Executor（执行）/ Reviewer（审查）
- **子 Agent 派发**：主 Agent 把子任务交给专门的子 Agent
- **通信设计**：共享状态、消息协议、结果汇总

## 常见协作模式

| 模式 | 结构 | 适用 |
|---|---|---|
| Supervisor（主管） | 主 Agent 分发任务，子 Agent 汇报 | 任务类型多样、需统一协调 |
| Pipeline（流水线） | A 的输出 → B 的输入 | 流程固定（写作→审校→排版） |
| Debate（辩论） | 多个 Agent 互相审查 | 需要高可靠性（代码审查、研究） |
| Swarm（群体） | 点对点协作，动态交接控制权 | 开放式复杂任务 |

## 什么时候需要多智能体

**先问自己：单 Agent + 好的工具能不能解决？**

需要多 Agent 的信号：
- 上下文互相污染（不同任务需要不同背景知识）
- 并行子任务（同时搜索多个来源）
- 角色冲突（生成者和审查者分开更客观）

## 成本警告

多 Agent = token 消耗倍增、调试难度倍增。**能用单 Agent 就别上多 Agent。**

### 代码案例：Supervisor 模式（主 Agent 分发 → 子 Agent 执行 → 主 Agent 验收）

```python
SUB_AGENT_SYSTEM = {
    "searcher":  "你是检索专家。只做搜索和整理事实，不做最终结论，输出带来源。",
    "writer":    "你是写作专家。基于给定素材写作，不自行编造事实。",
}

def run_sub_agent(role: str, task: str) -> str:
    """子 Agent：独立上下文，只看到分派给它的任务"""
    return run_agent(
        user_input=task,
        system=SUB_AGENT_SYSTEM[role],   # 每个子 Agent 一套独立系统提示
        max_turns=5,
    )

def run_supervisor(user_input: str, max_rounds: int = 3):
    plan = llm_json(                     # 1. 主 Agent 拆解并分派
        system='输出 JSON: [{"role":"searcher","task":"..."}]',
        user=user_input,
    )
    results = {}
    for step in plan:                    # 2. 逐个派发（可改成 asyncio 并行）
        results[step["role"]] = run_sub_agent(step["role"], step["task"])

    for i in range(max_rounds):          # 3. 主 Agent 验收
        review = llm_json(
            system='审查各子任务结果，输出 {"approved": bool, "feedback": "...", "redo": [{"role","task"}]}',
            user=f"任务：{user_input}\n结果：{json.dumps(results, ensure_ascii=False)}",
        )
        if review["approved"]:
            break
        for step in review["redo"]:      # 不合格 → 带着意见打回重做
            results[step["role"]] = run_sub_agent(step["role"], step["task"])

    return run_agent(f"基于已验收的素材输出最终结果：{json.dumps(results, ensure_ascii=False)}")
```

要点：
- 子 Agent **看不到主 Agent 的完整对话**（上下文隔离，防止污染）
- 验收循环带 `max_rounds` 上限（008 课可靠性原则）
- 每次派发把验收 feedback 一并传给子 Agent，否则它只会原样重做

## 思考题

1. Supervisor 模式下，主 Agent 如何判断子 Agent 的结果是否合格？

### 参考答案

三种由弱到强的手段，实践中组合使用：

**1. 结构化验收（最基础）**
让子 Agent 按约定格式返回，主 Agent 校验完整性：
```json
{"status": "success|failed", "summary": "...", "evidence": "...", "remaining": "..."}
```
缺字段、status=failed 就打回重做。检查的是**格式和显式信号**。

**2. 证据校验（中等）**
不只听结论，要求附证据，主 Agent 核对：
- 引用的文件路径是否真实存在
- 调用的工具记录是否匹配结论
- 数字/事实是否与工具返回值一致
防止子 Agent"编造完成"（hallucinated success）。

**3. 独立审查（最强）**
- 关键任务派一个 Reviewer 子 Agent 复核，或用不同模型交叉验证
- 可验证的任务直接跑机器断言：代码 → 跑测试，报表 → 校验数字合计

**通用技巧——明确"完成的定义"（DoD）**：派发任务时就把验收标准写进 prompt（"必须包含 X、覆盖 Y、不超过 Z"），否则主 Agent 只能凭感觉判断。

**兜底**：限制重试次数，失败后降级（报告人工介入），避免主/子 Agent 无限互相打回。
