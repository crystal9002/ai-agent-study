# 001 核心架构：Agent 循环

## 本课要点

Agent 的本质是一个循环（ReAct 模式）：

```
感知 → 规划 → 行动 → 观察 → 反思 → (回到感知)
```

- **LLM 是"大脑"**：负责推理、决策、选择工具
- **循环终止条件**：LLM 不再调用工具时，输出的文本就是最终答案
- 理解了这个循环，就理解了所有 Agent 框架的底层逻辑

## 为什么重要

几乎所有 Agent 框架（LangGraph、Claude Agent SDK、OpenAI Agents SDK）底层都是这个循环的工程化封装。

## 思考题

1. 如果去掉"观察"环节，Agent 会变成什么？
2. 循环什么时候应该停止？有几种停止方式？

### 参考答案

**1. 去掉"观察"环节 → 变成一次性生成（普通 LLM 调用）**

"观察"是把工具执行结果反馈给 LLM 的环节。没有它，LLM 只能凭自己参数里的知识作答：
- 能力退化：无法查实时数据、无法操作外部系统、无法知道上一步执行得对不对
- 变成"闭着眼睛做事"：发完指令就结束，出错了也不知道
- **观察环节 = Agent 与 Chatbot 的本质区别**

**2. 停止方式有 4 种**

| 方式 | 说明 | 场景 |
|---|---|---|
| LLM 主动停止 | 不再返回 tool_calls，直接输出文本 | 最常见、最自然的方式 |
| 循环上限 | 达到 max_turns 强制退出 | 防止死循环烧钱（必加） |
| 业务条件满足 | 某个工具返回"任务完成"标志 | 流程明确的自动化任务 |
| 外部中断 | 用户取消、超时、预算耗尽 | 生产环境的熔断保护 |

实践上应该**同时**保留 LLM 主动停止 + 循环上限两种。
