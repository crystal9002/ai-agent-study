# 05 · 生产化落地：从演示到可上线的 Agent

## 架构总览

```
用户请求 ──→ 会话/权限层 ──→ 规划节点（可人工确认计划）
                                │
              状态库(Checkpoint) ←┴→ 执行循环（工具网关：鉴权/限流/审计）
                                        │
                            人工确认(高危工具) / 重规划
                                        │
                                   汇总 → 输出 + 评估埋点
```

## 1. 状态持久化（LangGraph Checkpointer）

规划型 Agent 单次任务可能跑几十秒、几十次 LLM 调用，**断线/超时必须能续跑**：

```python
from langgraph.checkpoint.sqlite import SqliteSaver

app = graph.compile(checkpointer=SqliteSaver.from_conn_string("agent.db"))
app.invoke({"goal": g}, config={"configurable": {"thread_id": "user-42-task-7"}})
```

每个节点执行后状态自动落库；可从任意断点 `invoke` 恢复，也能查回完整执行历史做审计。原生版对应做法：自己把 `plan/results` 序列化存 DB，按任务 ID 恢复。

## 2. 人工确认（Human-in-the-loop）——规划型 Agent 的杀手锏

计划可见就该利用：**高危动作执行前停下来等人点头**。

```python
g.add_conditional_edges("plan", confirm_or_auto,
                        {"auto": "step", "wait": "__interrupt__"})
```

- 规划完成后展示计划 → 用户可改步骤、删步骤、否决
- 写操作工具（下单/付款/删数据）执行前再确认一次（LangGraph `interrupt()`）
- 只读工具自动放行

这是 Workflow 式审批与 Agent 自主性之间的平衡点，也是规划型模式比纯 ReAct 更适合企业场景的核心原因。

## 3. 工具网关

不要让 Agent 直连业务系统，中间加一层网关：

| 能力 | 做法 |
|------|------|
| 鉴权 | 工具级权限（用户能调哪些工具），参数级过滤（只查自己的订单） |
| 限流 | 每任务工具调用次数上限、每秒 QPS、LLM Token 预算 |
| 审计 | 谁、何时、以什么参数调了什么工具、返回什么 → 全量日志 |
| 超时/熔断 | 单工具超时转错误回填；下游故障时降级为跳过该工具 |
| 幂等 | 关键写工具带幂等键，防止重试重复下单 |

## 4. 终止与失控防护（上线前必查）

- [ ] 全局步数上限 + 每步 `max_iters` + 单任务总 Token 预算
- [ ] 死循环检测：连续 N 轮重复同一工具+同参数 → 强制终止
- [ ] 工具白名单：规划器提到的工具名不在注册表 → 忽略而非报错崩溃（原生版已处理）
- [ ] 输出长度限制与敏感信息过滤（日志脱敏）
- [ ] 超时兜底：任务级超时返回"部分结果 + 已完成步骤"

## 5. 评估

- **规划质量**：计划步骤数合理性、步骤可执行性（LLM-as-Judge 打分）、人工标注黄金计划对比
- **执行成功率**：任务完成率、步骤失败率、平均工具调用次数、平均耗时/成本
- **端到端**：最终结果正确性（模拟数据场景可做确定性断言：航班/酒店数据可校验）
- 回流：失败任务的完整状态快照入库 → 归因（计划差/工具错/模型幻觉）→ 修完跑回归

## 6. 成本与延迟

- 规划 + N 步 + 汇总 ≈ N+2 次 LLM 调用，其中每步内部还可能有多轮工具调用
- 优化：只读步骤结果做缓存；简单步骤用小模型（分级调度）；工具调用并行化（步骤无依赖时）
- 观测：每次 LLM/工具调用打点（耗时、token、参数），LangGraph 的 state 时间线天然可做数据源

## 7. 上线检查清单

- [ ] Checkpointer 持久化，任务可恢复可审计
- [ ] 计划确认 + 高危工具人工确认
- [ ] 工具网关：鉴权/限流/审计/超时
- [ ] 三重终止保险 + 死循环检测
- [ ] 评估集跑通，失败可归因
- [ ] Token/耗时/成功率监控看板
- [ ] 错误兜底：任何异常返回结构化失败，不裸抛堆栈
