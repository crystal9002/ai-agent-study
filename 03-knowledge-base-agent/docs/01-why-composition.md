# 01 · 为什么要把 RAG 包成 Agent：两种范式的分工

## 本课要点

- RAG 是**固定链路**（检索 → 生成），Agent 是**运行时由 LLM 决定控制流**
- 单轮事实问答用纯 RAG 更快更稳；**多步、组合、"工具 + 检索"混用**才需要 Agent
- 本教程 = 01 的检索能力 × 02 的循环骨架：`search_kb` 只是工具之一

## 两种范式先摆清楚

| | 纯 RAG（01 教程） | 知识库 Agent（本教程） |
|---|---|---|
| 控制流 | 写死：embed → search → generate，**一次检索一次生成** | LLM 运行时决定：查不查、查几次、还要不要算/写 |
| 检索次数 | 恰好 1 次（k 固定） | 0~N 次（模型按信息缺口自己补） |
| 能力边界 | 只会"查资料回答" | 检索 + 计算 + 写文件 + …（工具集可扩） |
| 延迟/成本 | 低且稳定 | 更高（N 轮 LLM 调用），但复杂问题才划算 |
| 失败模式 | 检索不到 → 答非所问 | 循环跑飞/漏检索 → 要 `max_iters` 与 prompt 合同兜底 |

判定标准仍然是那一条：**控制流是否由 LLM 在运行时决定**。纯 RAG 不是 Agent，
它是 Agent 的一个零件。

## 什么时候需要"查知识库的 Agent"

看三类问题的差别：

```
① 事实查找：  "团队版多少钱？"          → 一查一答，纯 RAG 就够
② 追问组合：  "团队版多少钱？50个人      → 查价格 → 算账 → 综合两份证据作答
              一年多少钱？"                （检索 + 计算，两次工具调用）
③ 任务型：    "查出团队版价格，用 calc   → 检索 → 计算 → 写文件，三种工具串起来
              算 50 人年费，写进 note"
```

- ① 用 Agent 是**杀鸡用牛刀**：多花 1~2 轮 LLM 往返，还引入循环失控风险
- ②③ 是纯 RAG **结构上做不到**的：固定链路里没有"第二次调工具"的出口
- 还有一类隐蔽需求：**答案要在多个来源之间交叉核对**（价格表 vs 计费规则 vs
  优惠条款），Agent 可以发多个不同角度的 query，纯 RAG 的单次 query 往往顾此失彼

反过来说，这三类**不该上 Agent**：高并发的客服一问一答（延迟敏感）、
可枚举的确定性流程（用 Workflow 更可控）、以及检索质量本身没调好的场景
——先回 01 教程把 Hit Rate 修上来，Agent 救不了烂检索。

## 本教程的场景设定

企业内部"星云笔记"知识库助手，`data/` 自带三份文档：

| 文档 | 内容 | 典型问题 |
|------|------|----------|
| `product_manual.md` | 产品手册：功能、版本差异、限制 | "团队空间最多多少人？" |
| `pricing_faq.md` | 价格与计费 FAQ | "团队版年付多少？" |
| `api_guide.md` | 开放 API：认证、接口、限流、错误码 | "限流是多少？" |

Agent 手里有 4 个工具：`search_kb`（检索）、`calc`（算账）、`write_note`（写笔记）、
`list_notes`（看笔记）。**检索只是其中之一**——这正是它比纯 RAG 多出来的部分。

## 思考题

1. 用户问"团队版几个人可以用"，纯 RAG 和知识库 Agent 的执行链路分别是什么？
   哪个更合适？
2. 为什么把 `calc` 也包进 Agent，而不是让检索结果里直接写死所有计算结果？
3. "检索次数由模型决定"带来的最大工程风险是什么？本教程在哪两处设了防线？

## 参考答案

1. 纯 RAG：query → 向量+BM25 召回 → 拼 prompt → 生成，**1 次检索 1 次生成**，
   单轮事实问题就该这么走。Agent：LLM 判断需要检索 → `search_kb` → 证据回填 →
   生成。链路等价但多一轮 LLM 往返，**此场景纯 RAG 更合适**。
2. 知识是变的、组合是无限的：50 人、80 人、3 年、叠加教育折扣……枚举不完。
   让模型按问题现场编排"查到单价 → `calc` 算"，知识库只维护**事实**，
   计算交给工具，两边都可独立演进（也避免模型心算出错）。
3. 风险是**循环跑飞/无限调用**（成本与延迟失控）。防线：`kba/agent.py` 的
   `max_iters` 轮数上限（兜底返回中止说明），以及 `SYSTEM` 合同限定"信息齐了
   就给结论"；工具侧错误转 `{"error":…}` 回填，让模型**自我纠错而不是反复重试同一调用**。
